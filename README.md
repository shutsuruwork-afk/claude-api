## P2P 接続テスト (GitHub Pages)

`index.html` は WebRTC DataChannel で複数端末が直接つながり、データが同期するかを確認するページです。

### 使い方
1. ページを開いてルーム名を決め「参加」→「招待 URL をコピー」で他の端末に送る
2. 3 台以上で同じ URL を開くと、自動的に全員同士（フルメッシュ）で接続
3. 「同期状況」の表で、各端末から見た接続経路とハッシュの一致を確認

### 機能
| 機能 | 内容 |
|---|---|
| 同期状況マトリクス | 全端末 × 全端末の接続経路（H=同一LAN / S=NAT越え / R=TURN中継 / ×=失敗）、RTT、共有データのハッシュ |
| 共有データ | 12×12 のマス目とチャット。直接つながらない組み合わせがあっても他端末経由で同期 |
| 一斉書き込みテスト | 全端末が同時に 50〜1000 回書き込み、全員のハッシュが一致するまでの時間を計測 |
| 速度テスト | 接続ごとに 1/8/32 MB を送ってスループットを計測 |
| 切断テスト・自動再接続 | 接続を意図的に切って自動復旧までの時間を計測。Wi-Fi ⇄ モバイル回線切替の確認にも |
| ルーム窓口の引き継ぎ | 最初の参加者が抜けても、残った端末が自動で窓口役を引き継ぐ |
| ネットワーク診断 | NAT の種類（Cone / 対称型）、STUN 応答、IPv6、TURN の動作を確認 |
| 手動モード | PeerJS サーバーなしで SDP をコピペして接続（同期テストにも参加） |
| 設定 | 表示名、TURN サーバー、TURN 中継のみモード、自前のシグナリングサーバー |

### おすすめのテスト順
1. 同じ Wi-Fi で 3 台 → 全部 `H` になるか
2. 1 台をモバイル回線に → その行・列が `S` になるか
3. モバイル回線同士・会社/学校 Wi-Fi → `×` が出るか（出たら TURN が必要）
4. 各構成で「一斉書き込みテスト」→ 全員一致するか
5. 接続中に Wi-Fi をオフ/オン → 自動再接続されるか
