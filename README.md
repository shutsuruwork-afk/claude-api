## P2P 接続テスト (GitHub Pages)

`index.html` は WebRTC DataChannel で複数端末が直接つながり、データが同期するかを確認するページです。

### 通信先（ワイルドカードなし）
`index.html` は 1 ファイルで完結しています（PeerJS を同梱）。**ダウンロードしてブラウザで直接開けば**、
ページを置くサーバーへの通信も不要です。

| 用途 | 宛先 | 備考 |
|---|---|---|
| シグナリング（最初の接続情報の交換） | `wss://0.peerjs.com` のみ | 設定で自前サーバーに変更可。手動モードなら不要 |
| STUN（NAT 越え用、UDP） | `stun.l.google.com:19302`, `stun1.l.google.com:19302` | 設定で変更・削除可。同一 LAN だけなら不要 |
| データ本体 | 端末同士の直接通信 | サーバーを経由しない |

GitHub Pages など Web 上で開く場合は、上記に加えてそのページのホストへの通信が必要です。

### 使い方
- **全員が同じ版のファイルを使ってください。** ページ上部に「版 2026-…」と出ます（結果レポートにも入ります）。最新は GitHub のこのブランチの `index.html` です。
- ページの「テスト（上から順に）」にある **1 台テスト → 全員で自動テスト → 長時間テスト** を順に実行します。手順と結果の読み方は [TESTING.md](TESTING.md)。以下は手動で試す場合（プレイグラウンド）。

1. ページを開いてルーム名を決め「参加」→「招待 URL をコピー」で他の端末に送る（ファイルを直接開いている場合はボタンが「ルーム名をコピー」になるので、ルーム名を伝える）
2. 3 台以上で同じ URL を開くと、自動的に全員同士（フルメッシュ）で接続
3. 「同期状況」の表で、各端末から見た接続経路とハッシュの一致を確認

### 機能
| 機能 | 内容 |
|---|---|
| **1 台テスト** | 相手がいなくても、ページの中に「仮の相手」を作って自動テストを一通り流す。この端末・ブラウザ・サーバー接続が使えるかを確認（端末同士のネットワークは未検証と表示） |
| **自動テスト** | ボタン 1 つで端末単体の確認と全員での通信テストを順に実行し、「✅ 使える / ⚠️ 条件付き / ❌ 使えない / ❔ 未検証」を判定。結果は全参加者の端末に保存 |
| 保存した結果・比較 | 自動テストの履歴（端末内に保存）、.md / .json での保存、他の人の結果の読み込み、条件ごとの比較表 |
| 同期状況マトリクス | 全端末 × 全端末の接続経路（H=同じネットワーク内で直接 / S=別ネットワークと直接 / D=直接だがどちらか不明 / R=TURN中継 / ×=失敗）、RTT、共有データのハッシュ |
| 共有データ | 12×12 のマス目とチャット。直接つながらない組み合わせがあっても他端末経由で同期。「全消去」はマス目・チャット・操作ログを全端末から消す |
| 一斉書き込みテスト | 全端末が同時に 50〜1000 回書き込み、全員のハッシュが一致するまでの時間を計測 |
| 速度テスト | 接続ごとに 1/8/32 MB を送ってスループットを計測 |
| リアルタイム通信テスト | 全員が 20〜60 回/秒で送り合い、p50/p95/p99・ロス・ジッター・途切れ・時計ずれを「確実（再送あり）」「高速（再送なし）」で比較し、ゲーム向けの判定を表示 |
| 長時間テスト | 全員が 20 回/秒で 5〜60 分送り合い、1 分ごとの遅延・ロス、切断と自動復帰を記録して「ゲーム 1 回分もつか」を判定。結果は自動テストと同じ履歴に保存 |
| 結果レポート | 上記をテキストにまとめてコピー（IP は伏せ字） |
| 切断テスト・自動再接続 | 接続を意図的に切って自動復旧までの時間を計測（自動テストでは全相手を順に切断）。Wi-Fi ⇄ モバイル回線切替の確認にも |
| ルーム窓口の引き継ぎ | 最初の参加者が抜けても、残った端末が自動で窓口役を引き継ぐ |
| つながらない理由の表示 | 相手の発見はシグナリング経由で行うので、端末同士の通信が塞がれていても「相手は見つかったが直接つながらない」と分かる。「LAN 内の直接接続を助ける」（マイク許可でローカル IP を相手に伝える）で回避できるかも試せる |
| ネットワーク診断 | NAT の種類（Cone / 対称型）、STUN 応答、IPv6、TURN の動作を確認（IP アドレスは画面にも出さない）。自動テストでは TURN を経路別（UDP / TCP / TLS）に確認 |
| QR コード / 短いコードで接続 | サーバーなしで、QR を 1 往復読み合うだけで接続。カメラがなければ約 115〜135 文字のコードを入力（打ち間違い検出つき） |
| 手動モード | PeerJS サーバーなしで SDP をコピペして接続（同期テストにも参加） |
| 設定 | 表示名、TURN サーバー、TURN 中継のみモード、自前のシグナリングサーバー |

## 開発用の自動テスト（E2E）

`tests/e2e.js` がローカルの PeerJS サーバーと Playwright で複数台構成を再現し、接続・同期・窓口の引き継ぎ・手動モード・自動テスト・不正な入力への耐性を確認します（外部通信なし。長時間テストと TURN 中継もローカルの TURN サーバーで確認）。push すると GitHub Actions でも実行されます。

```sh
cd tests && npm install && npx playwright install chromium && npm test
node e2e.js --list     # テストの一覧（分類ごと）
```
